Agent 系統

目標 → 動作 → 結果 → 下一步

任務可能需要查資料、呼叫工具，再依回傳結果繼續處理。[S03][S04]

工具讓系統能取得外部資訊或執行動作；每次動作仍需看權限和風險。

02 / 工作定義

Agent = 帶目標的
模型 + 行動迴圈

模型理解任務、選擇下一步；工具回傳觀察後，系統再決定要繼續、調整或停止。[S02][S03]

要有

目標與規則
做什麼、何時算完成、哪些事不能做。

也要有

回饋與界限
看得到工具結果，也知道何時停止或請人確認。

「Agent」在不同文章中有不同範圍；這裡採用方便入門的工作定義。[S02]

03 / 系統零件

六個零件，串成一個任務

01

02

05

04 / Agent loop

動作之後，要看結果

目標要解決什麼？
上下文規則、資料、狀態
模型選擇回答或動作
工具搜尋、計算、查詢
觀察讀取工具回傳
判斷完成、再試或停止
若未完成且仍在界限內，回到「模型」選下一步。

ReAct 論文研究推理步驟與任務行動交錯的做法；實際產品的循環由系統設計決定。[S03][S04]

05 / 不同控制方式

Workflow 和 Agent
不是誰取代誰

Workflow

路徑先寫好

程式預先安排步驟，結果較容易預測。任務固定時常是好選擇。

固定步驟好檢查
Agent

依結果動態選擇

模型可依任務決定呼叫哪個工具或接著做什麼。變化多時更有彈性。

動態路徑需設界限
Anthropic 用這個區分說明兩種架構；實務系統可以混合使用。先選能完成任務的最簡單方案。[S02]

06 / 工具與 MCP

MCP 像連接埠，
不是判斷大腦

Model Context Protocol（MCP）提供 AI 應用連接外部資料、工具和工作流程的共同方式。[S05]

資料來源

讀取資訊

例如本機檔案或資料庫。

工具

執行功能

例如搜尋或計算器。

工作流程

連接任務

使用外部系統提供的能力。

連得上 ≠ 有權限 ≠ 結果正確。應用仍要驗證授權、工具輸入和回傳內容。

07 / 可靠性

把安全檢查放進流程

常見失誤

  • 誤解任務或漏掉限制
  • 選錯工具、參數或資料
  • 把含糊結果說得太確定
  • 沒有限制步數或高風險動作

設計檢查點

  • 先定義完成條件與停止界限
  • 只給完成任務需要的權限
  • 重要或不可逆操作先請人確認
  • 保留 trace，再用案例檢查改善

Agentic 系統可能增加延遲和成本；應用簡單 Workflow 能處理的任務，不必加上自主迴圈。[S02][S04]

08 / 帶走三件事

Agent 能行動，
所以更需要界限

記住 01

Agent 不只是會回答，也會在任務中使用工具和回饋。

記住 02

工具、Workflow、MCP 是不同層次的東西，別混為一談。

記住 03

先選簡單方案；給必要權限，設停止與人工檢查點。

想一想：若 Agent 能替你安排會議，哪一步必須先請你確認？
