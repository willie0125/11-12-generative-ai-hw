# AI Agent 是什麼？

## 一句話理解

AI Agent 是一種以模型為核心、帶著任務目標，能取得上下文、選擇並呼叫工具，再根據回傳結果決定下一步的系統。它會在一個有界限的執行循環中工作；不代表可以不受限制地自行行動。[S02][S03][S04]

## 和一般聊天的差別

一般聊天常見模式是「收到問題 → 產生回答」。Agent 系統則可能變成「收到目標 → 決定下一個動作 → 呼叫搜尋、程式或其他工具 → 讀取結果 → 再回答或繼續」。ReAct 論文研究了行動與環境觀察交錯的方式；Agent SDK 文件則說明工具、執行循環、狀態和追蹤等實作元件。[S03][S04]

## 常見組成

1. **目標與指令**：說清楚任務、輸出格式和不可執行的事。
2. **模型**：理解請求，產生答案或提出下一步工具動作。
3. **上下文**：任務所需的對話、文件、狀態或使用者授權。
4. **工具**：例如搜尋、計算、查資料庫或呼叫應用程式。
5. **執行循環與停止條件**：處理工具結果、判斷是否繼續，並在步數或時間界限到達時停止。
6. **檢查與紀錄**：權限、人工覆核、錯誤處理及 trace 有助於降低風險並理解執行情形。[S03][S04][S05]

## 用校園行程助手想像

使用者問：「幫我找星期五下午有空的時段，並列出要帶的資料。」在**未授權更動行事曆**的情況下，Agent 可以先查行事曆（工具）、讀取結果（觀察）、比對時間，再列出空檔；若要新增事件，則應要求明確權限或人工確認。這是說明流程的假想例子，並非任何來源提供的效能保證。

## 小結

判斷一個系統是否具有 Agent 特性，別只看它會不會聊天；要看它是否在任務中使用工具或環境回饋，並依結果調整下一步。不同文章對 Agent 的界定不同，因此這裡採用的是為初學者服務的工作定義。[S02]
